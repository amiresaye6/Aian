# Contributing to Aian

First off, thank you for considering contributing to Aian! It's people like you that make Aian such a great platform.

## Where do I go from here?

If you've noticed a bug or have a feature request, make sure to check our [Issues](https://github.com/amiresaye6/Aian/issues) to see if someone else has already created a ticket. If not, go ahead and make one!

## Fork & create a branch

If this is something you think you can fix, then fork Aian and create a branch with a descriptive name.

## Get the development environment running

Please refer to our [README.md](README.md) for detailed instructions on how to set up Aian locally using Docker or running the client and server locally.

## Implementing your changes

- Ensure your code follows the existing style and conventions.
- Be sure to check the `docs/` folder for architectural guidelines, such as the `Knowledge_Assembler_Guide.md` and `SKILL_DEVELOPMENT_GUIDE.md`.
- If you've added code that should be tested, add tests.
- If you've changed APIs, update the documentation.
- Ensure the test suite passes (`npm run test` in the `server` directory).

## Submit a Pull Request

At this point, you should switch back to your master branch, make sure it's up to date with Aian's master branch.
Then push your branch to your fork and submit a pull request!

Please fill out the Pull Request template provided when you open a PR. It will help us review your code faster.

## Code of Conduct

By participating in this project, you are expected to uphold our [Code of Conduct](CODE_OF_CONDUCT.md).
